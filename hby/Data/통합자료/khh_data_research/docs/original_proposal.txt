# LG 가전 구독 이사 의사결정 AI Agent — 최종 기획안

**내가 이 프로젝트를 맡는다면, 기존 주제를 버리지 않고 LG 내부 시스템을 가상으로 구현해서 완성도 있는 AI Agent를 만들겠어.**

단순히 위약금을 계산해 주는 게 아니라, 고객이 이사를 앞두고 겪는 문제를 **AI가 판단하고 실제 업무 처리까지 연결하는 서비스**로 만드는 거야.

## 1. 내가 만들 서비스

### 서비스명: LG Move Care

**"이사할 때도, 가전 구독은 번거롭지 않게."**

| 구분 | 내용 |
| --- | --- |
| 제안 기업 | LG전자 |
| 서비스 대상 | 이사를 앞둔 LG 가전 구독 고객 |
| 핵심 문제 | 복잡한 계약 조건과 비용 때문에 해지·이전을 결정하기 어려움 |
| AI Agent 역할 | 고객 계약 확인 → 규정 검색 → 비용 산정 → 선택지 비교 → 이전설치 예약 |
| 핵심 기술 | RAG + FastMCP + LLM + Mock LG 시스템 |
| 구현 형태 | React 기반 웹서비스 |
| LG 기대 효과 | 구독 고객 유지, 상담 업무 감소, 고객 경험 개선 |

### 가장 중요한 결정: 제품은 워시타워 1종으로 제한

원래 기획은 세탁기와 건조기였는데, 나는 **워시타워 1종**을 추천해.

실제 LG전자 안내를 확인해 보니 워시타워는 조건에 따라 구독 계약기간 중 1회 무상 철거·재설치를 제공하지만, 제품 운반은 포함되지 않아. 따라서 이 혜택과 운송을 분리해서 모델링할 수 있어. LG전자

그리고 중요한 사실 하나를 발견했어.

**기존 기획서의 회수비는 오래된 기준이야.**

LG 공식 FAQ에는 2026년 3월 24일 기준 워시타워 회수비가 111,000원으로 안내되어 있어. 실제 계약에 적용되는 금액은 계약서를 확인해야 해. LG전자

따라서 데이터는 이렇게 나눌 거야.

- **실제 데이터:** LG 공식 약관, FAQ, 구독 서비스 규정
- **가상 데이터:** 고객 계약, 제품 정보, 이전설치 비용 견적, 기사 일정, 예약 현황

이렇게 하면 실제 규정에 근거한 RAG를 구현하면서도 LG 내부 시스템을 이용하는 것처럼 데모할 수 있어.

## 2. 전체 프로젝트 진행 구조

전체 흐름은 이렇게 잡겠어.

**데이터 분석 → 인사이트 도출 → 페르소나 → CX 문제 정의 → AI Agent 설계 → 구현 → 평가 및 개선**

| 단계 | 목표 | 최종 산출물 |
| --- | --- | --- |
| ① 데이터 분석 | 고객이 겪는 문제를 데이터로 확인 | 인사이트 리포트 |
| ② 페르소나 | 문제를 겪는 대표 고객 설정 | 페르소나 카드 |

여기서 중요한 건 **데이터 분석이 Agent를 만들기 위한 형식적인 절차가 되면 안 된다는 거야.**

가상 데이터는 고정된 규칙에 따라 생성하고, 어떤 값이 가정인지 명시하겠어.

| 거주 | 서울 마포구 전세 |

가상 페르소나이며, 실제 조사 응답자로 소개하지 않아.

> "워시타워 구독한 지 1년 반 정도 됐는데, 다음 달에 이사하거든요. 그냥 해지하는 게 나을까요? 아니면 옮기는 게 나을까요? 위약금도 모르겠고 이전설치 비용도 모르겠어요."
> 

현재 고객은 약관, 계약서, 이전설치 안내를 각각 확인해야 해.

게다가 설치 가능 여부와 예약 일정까지 알아봐야 하지.

## 6. CX 문제 정의

나는 문제를 이렇게 정의하겠어.

**"이사를 앞둔 가전 구독 고객은 자신의 계약 조건과 이전설치 가능 여부를 한 번에 확인하기 어려워, 해지와 이전 중 어떤 선택을 해야 할지 판단하고 실행하는 데 불편을 겪는다."**

여기서 해결할 CX는 두 가지가 아니라 하나야.

**이사 상황에서 고객의 계약 의사결정부터 실행까지 이어지는 복잡한 과정을 해결한다.**

기존과 개선 후를 비교하면 다음과 같아.

| As-Is | To-Be |
| --- | --- |
| 계약서 직접 확인 | Agent가 Mock 계약 DB 조회 |
| 약관과 FAQ 개별 검색 | RAG로 관련 규정 검색 |
| 해지 비용 직접 계산 | Tool이 계산 |
| 이전설치 비용 별도 문의 | Mock 견적 시스템 조회 |
| 해지와 이전 중 고민 | 근거 있는 선택지 비교 |
| 이전설치 예약 별도 진행 | Agent에서 예약 완료 |

**AI를 사용한 이유가 단순 계산이 아니라 여러 정보를 결합해서 고객의 행동까지 처리하기 위함이라는 점**을 강조할 거야.

# PART 3. AI Agent 설계

## 7. 핵심 시나리오

실제 서비스처럼 시연하겠어.

### STEP 1. 고객이 Agent에게 질문

👩 고객

> "다음 달에 이사하는데 구독 중인 워시타워를 가져가는 게 나을까요? 해지하는 게 나을까요?"
> 

🤖 Agent

> "현재 구독 중인 제품과 계약 조건을 확인해 드릴게요."
> 

### STEP 2. LG 계약 시스템 조회

Agent가 `get_customer_contract` Tool을 호출해.

**Mock LG 시스템 응답**

```
{
  "customer_id": "C001",
  "product": "LG WashTower",
  "monthly_base_fee": 59000,
  "mandatory_months": 36,
  "used_months": 18,
  "free_reinstallation_available": true,
  "contract_status": "active"
}
```

이건 사용자가 직접 계약 정보를 일일이 입력하는 것보다 훨씬 자연스러워.

데모에서는 가상 고객 계정을 선택하는 방식으로 로그인 과정을 대신할 수 있어.

### STEP 3. RAG를 이용한 계약 규정 검색

Agent가 관련 규정을 검색해.

**검색 대상**

- LG 가전 구독 FAQ
- LG 구독 이용약관
- 워시타워 이전설치 안내
- 계약 시점별 적용 규정

Agent가 찾아야 하는 내용은 다음과 같아.

- 현재 계약의 중도해지 위약금 기준
- 회수비
- 무상 철거·재설치 적용 여부
- 별도 운송 필요 여부

단순한 정보 검색이 아니라 **고객의 계약과 실제 약관을 대조하는 것**이야.

### STEP 4. 해지 비용 계산

Agent가 계산 Tool을 실행해.

가상 계약에 적용되는 위약금 비율을 20%로 설정했다면,

| 항목 | 금액 |
| --- | --- |
| 월 기본요금 | 59,000원 |
| 의무사용기간 잔여 | 18개월 |
| 예상 위약금 | 212,400원 |
| 회수비 | 111,000원 |
| **예상 해지 비용** | **323,400원** |

위약금은 가상 계약에 공식 FAQ의 해당 산식을 적용한 시뮬레이션 결과야. 회수비도 이 가상 계약에 2026년 3월 기준 금액이 적용된다고 가정했어.

미납금, 사은품 비용 등의 추가 비용은 없는 사례로 설정한 거야.

### STEP 5. 이전설치 비용 조회

Agent가 `get_relocation_quote` Tool을 호출해.

가상 견적 시스템에 다음 결과가 있다고 가정하자.

| 항목 | 금액 |
| --- | --- |
| 기존 제품 철거 | 0원 |
| 제품 운송 | 80,000원 |
| 새집 재설치 | 0원 |
| **예상 이전 비용** | **80,000원** |

여기서 80,000원은 **Mock 견적**이야. 실제 LG 운송 요금이 아니야.

또한 새집 설치 환경이 적합하다는 가상 사전 확인 결과가 있어야 해.

### STEP 6. 비교 결과 제공

Agent가 화면에 결과를 보여줘.

#### 이사할 때 발생하는 예상 일회성 비용

|  | 해지 | 이전 |
| --- | --- | --- |
| 예상 비용 | 323,400원 | 80,000원 |
| 구독 유지 | ❌ | ✅ |
| 제품 계속 사용 | ❌ | ✅ |
| 추가 확인 | 해지 정산 | 설치 환경 |

**이전 선택 시 당장 발생하는 예상 비용은 243,400원 적어.**

하지만 여기서 주의할 점이 있어.

이전할 경우 월 구독료는 계속 발생하고, 해지할 경우에는 대체 가전 마련 비용이 필요할 수 있어.

따라서 Agent가 무조건 "이전하는 게 243,400원 이득입니다"라고 말하면 안 돼.

**일회성 비용과 향후 사용 비용을 구분해서 알려줘야 해.**

그 후 고객에게 새집에서도 워시타워를 계속 사용할 계획인지 확인해서 적절한 선택을 안내하는 거야.

### STEP 7. 이전설치 예약

👩 고객

> "새집에서도 계속 쓸 거예요. 그러면 이전설치 예약해 줘."
> 

🤖 Agent

> "새집 주소와 설치 환경을 확인한 뒤 예약 가능한 날짜를 조회하겠습니다."
> 

Agent는 Mock 설치 일정 시스템을 조회해.

예약 가능한 날짜와 시간이 화면에 표시돼.

고객이 날짜를 선택하고 최종 확인 버튼을 누르면 예약 Tool이 실행돼.

**예약 완료**

- 예약번호: MOVE-20261025-001
- 제품: LG 워시타워
- 고객: 이서연
- 방문 일정: 2026년 10월 25일 오후 2시
- 예약 상태: 확정 (데모)
- 제품 운송: 별도 Mock 운송 서비스

실제 LG에 예약한 것이 아니라는 표시를 명확하게 넣을 거야.

이렇게 하면 고객이 단순히 정보를 듣고 끝나는 게 아니라 실제로 하나의 업무를 완료하는 경험을 제공할 수 있어.

# PART 4. 시스템 아키텍처

## 8. 기술 스택

나는 최대한 단순하게 만들겠어.

| 구분 | 기술 |
| --- | --- |
| Frontend | React + TypeScript + Vite |
| UI | Tailwind CSS + shadcn/ui |
| Backend | FastAPI |
| AI Agent | LangChain |
| LLM | OpenAI API |
| RAG | ChromaDB |
| Tool Server | FastMCP |
| Mock DB | SQLite |
| 데이터 분석 | Python + Pandas + Matplotlib |

Node.js는 제거하겠어.

현재 일정에서는 API 서버를 두 개 운영할 이유가 크지 않아.

### 전체 아키텍처

```
                  [React Web]
                       │
                       ▼
                   [FastAPI]
                       │
                       ▼
                [Single AI Agent]
                       │
           ┌───────────┴───────────┐
           │                       │
           ▼                       ▼
      [RAG 검색]              [FastMCP Tools]
           │                       │
           ▼                       ▼
       ChromaDB               Mock LG DB
           │                       │
     LG 약관·FAQ         고객 계약 / 이전 견적
                        기사 일정 / 예약 정보
```

## 9. 필요한 MCP Tool

**핵심 Tool은 5개만 구현하겠어.**

| Tool | 기능 |
| --- | --- |
| `get_customer_contract` | 고객 계약 조회 |
| `search_contract_terms` | 계약 규정 RAG 검색 |
| `calculate_termination_cost` | 해지 비용 계산 |
| `get_relocation_quote` | 이전설치 견적 및 가능 여부 조회 |
| `manage_relocation_booking` | 예약 가능 시간 조회 및 고객 확인 후 예약 |

이 다섯 개로 정상 시나리오를 완료할 수 있어.

비용 계산은 LLM에 맡기지 않고 코드에서 처리해.

그리고 약관 검색 결과와 고객 계약 조건이 충돌하면 임의로 계산하지 말고 확인 필요 상태로 전환하도록 하겠어.

# PART 5. 프론트엔드 설계

## 10. 웹사이트 화면 구성

**채팅창만 있는 서비스로 만들지 않겠어.**

LG전자에 제안하는 프로젝트이기 때문에 고객이 실제 서비스를 사용하는 듯한 느낌이 중요해.

### 화면 1. 고객 대시보드

가상 로그인된 고객의 구독 현황을 보여줘.

- LG 워시타워 제품 카드
- 월 구독료
- 계약 시작일
- 잔여 의무사용기간
- 이사 준비 시작하기 버튼

### 화면 2. AI Agent 상담

왼쪽에는 AI 채팅, 오른쪽에는 진행 상황을 표시해.

진행 단계는 다음과 같아.

**계약 조회 → 약관 확인 → 비용 비교 → 예약**

Agent가 Tool을 실행할 때 어떤 작업을 하는지 시각적으로 보여줄 거야.

### 화면 3. 비용 비교 카드

해지와 이전의 예상 비용을 카드 형태로 보여줘.

사용자는 각 선택지의 비용 구성과 조건을 펼쳐볼 수 있어.

특히 출처와 Mock 견적 여부를 구분할 거야.

### 화면 4. 이전설치 예약

달력 형태로 예약 가능 일정을 보여줘.

방문 일정을 선택하면 최종 확인을 거쳐 예약 완료 화면으로 이동해.

**디자인은 LG의 브랜드 분위기를 참고하되, 3D 같은 고비용 효과보다 제품 이미지·카드 전환·단계별 애니메이션에 집중하겠어.**

# PART 7. LG전자 제안 가치

## 12. LG가 왜 이 서비스를 도입해야 하는가?

LG 입장에서 기대할 수 있는 효과는 세 가지야.

**첫 번째. 구독 고객 유지**

고객이 비용이나 절차를 몰라 해지를 고려할 때, 이전이라는 선택지를 투명하게 제시할 수 있어.

다만 실제 해지율이 낮아지는지는 별도 실험이 필요해.

**두 번째. 고객센터 업무 부담 감소**

계약 조건 확인, 기본적인 예상 비용 계산, 이전설치 일정 확인과 같은 반복적인 업무를 Agent가 수행할 수 있어.

**세 번째. 고객 신뢰도 향상**

해지 비용을 숨기지 않고 계약 조건과 선택지를 함께 보여줘서 고객이 납득 가능한 결정을 내리도록 돕는 거야.

LG에 제안할 때는 단순히 해지를 방어하는 도구가 아니라 **고객이 스스로 올바른 선택을 하도록 돕는 서비스**라고 설명하겠어.

# 14. 그래도 이 기획의 약점은 무엇인가?

가상 데이터를 사용할 수 있어도 해결되지 않는 문제가 있어.

| 위험 요소 | 대응 계획 |
| --- | --- |
| 이사가 실제 구독 분쟁의 주요 원인이라는 직접 증거 부족 | 일반 계약 정보 문제를 데이터로 입증하고, 이사는 적용 시나리오로 설정 |
| 내부 데이터가 가상이라 현실성과 차이 발생 | 공개 약관을 기준으로 Mock 계약을 설계하고 가정을 명시 |
| 이전설치 비용이 가상 | 실제 비용처럼 표시하지 않고 시뮬레이션으로 구분 |
| 비용 비교만으로 전체 경제성 판단 불가 | 일회성 비용·향후 구독료·대체 제품 비용을 구분 |
| Agent가 단순한 계산기처럼 보일 위험 | 계약 조회부터 예약까지 실제 상태가 바뀌는 워크플로 구현 |
| 실제 LG 시스템과 연동되지 않음 | 내부 시스템 연동 가능성을 보여주는 PoC로 제안 |

이 부분은 발표에서 숨기지 않겠어.

오히려 한계를 명확하게 설명하는 편이 신뢰도가 높아.
