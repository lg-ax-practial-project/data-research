# LG TV MVP 기능 선택안 — 팀 승인 전 제안

작성일: 2026-10-02. 최신 실행 계획의 LG TV 범위를 따른다. 기존 4품목 데이터는 재활용 참고자료로 보존한다. 팀 승인 없이 범위·분담을 확정하지 않는다.

## 우리가 만들 것을 쉽게 설명하면

**“LG TV에 이상이 생긴 사람이 지금 확인할 것, 아직 모르는 조건, 준비할 증빙을 정리하고 수리 이후의 변화를 이어서 기록하는 상담 준비 Agent.”**

고장 원인을 확정하거나 교환·환급을 승인하는 서비스가 아니다. 공식 근거·조건과 다음 행동을 안내한다. 실제 LG 접수·수리 일정·고객 계정 연동은 공식 시스템 연결 없이 수행하지 않는다.

## 대상과 문제 — 검증할 가설

대상 제안: LG TV 이상을 처음 겪었거나 수리 후 같은 증상이 재발했으며, 모델·구매 증빙·점검 결과·수리 날짜 중 일부를 모르는 사용자.

‘어르신 전체’, ‘모든 가전 사용자’로 넓히지 않는다. 디지털 취약층의 어려움이 검증됐다고 말하지 않는다. 특정 연령을 핵심 타깃으로 삼으려면 추가 고객 근거가 필요하다.

문제 가설: 문서 설명이나 준비물 목록을 받아도 사용자가 자신의 조건을 확인하고 실제 결과·날짜·증빙을 정리하는 과정이 남을 수 있다. 근거는 [6개 가상 시나리오 1차 비교](../tv_user_research_20261002/서비스비교_1차종합.md)이며 실제 고객 경험 빈도 자료는 아니다.

## 기존 기능과 추가 검증할 부분

기존 응답에서는 자가 점검·보증·증빙 목록·서비스 연결을 확인했다. 따라서 단순 검색·요약·이미지·친절한 말투를 유일한 차별점으로 삼지 않는다.

추가 검증할 가설: **모르는 조건을 확인하고, 사용자가 제공한 점검 결과·수리 기록을 다음 질문과 상담 준비에 연결하는 흐름.** 기존 계정·예약·상담 전체 시스템에 이 기능이 없다고 확인한 것은 아니다. 시장에서 최초·유일하다는 주장도 하지 않는다.

## 우선 구현 후보

| ID | 기능 | 최소 결과물 | 연결 근거 | 사용 전 조건 |
| --- | --- | --- | --- | --- |
| F01 | 상황과 미확인 정보 정리 | 첫 이상/재발/지연 구분, 모델·증빙·날짜 확인/미확인 카드 | S02·S03·S05·S06 | 사용자의 말과 진단 확인 사실을 구분. ‘같은 증상’을 ‘동일 하자’로 자동 확정하지 않기 |
| F02 | 한 단계 점검과 결과 기록 | 현재 점검 1개, 결과/모름 입력, 다음 질문 | S01 후속·S02·S04 | 공식·모델 적합성·안전 검수를 통과한 단계만 사용. 모델 불명이면 식별 지원/전문 점검 연결 |
| F03 | 조건별 공식 근거 안내 | 관련 문서, 적용 조건, 미확인 항목, 원문 링크 | S03 링크·계산, S05 반복 고장 | 제품·주장·링크·정책 버전 대조. 법적 결과/무상 여부를 확정하지 않기 |
| F04 | 수리 타임라인·증빙 상태 | 구입/접수/인수/점검/수리/재발 기록, 증빙 확보/미확보 | S05·S06 | 사용자가 입력한 사건만 기록. 방문 횟수와 실제 수리 횟수 분리. 공식 일정 조회로 표현하지 않기 |
| F05 | 상담 준비 요약 | 증상·점검 결과·구매/수리 기록·부족한 자료·문의할 질문 | S05·S06, 전체 후속 연결 가설 | 정리본은 실제 접수 완료가 아님. 빠진 날짜·진단·승인 결과를 만들지 않기 |

F01·F04·F05는 정보 정리부터 설계할 수 있다. F02·F03의 특정 안내·판정·계산은 검수가 끝난 범위로 제한한다. 이는 개발 착수 명령이 아니라 범위 제안이다.

## 대표 데모 2개 — 제안

### A. 첫 이상: 소리만 나고 화면 없음

자연어 입력 → 모델/외부기기/점검 상태 미확인 카드 → 검수된 점검 1개 → 결과 또는 ‘모름’ 입력 → 다음 안내/전문 점검 연결 → 상담 준비 요약.

메뉴나 모델을 모르면 아는 것처럼 진행하지 않는다. 보증기간 이내라는 추정만으로 무료라고 약속하지 않는다. 전문가 진단과 사용자 관찰을 구분한다.

### B. 수리 후 화면 증상 재발

자연어 입력 → 구매/수리/재발 날짜와 작업 내역 질문 → 실제 수리·단순 방문 구분 → 타임라인과 증빙 상태 → 검수된 반복 하자 조건의 충족/미충족/미확인 표시 → 상담 준비 요약.

사례 입력이 정보 부족이면 결과도 ‘확인 필요’가 정상이다. 조정 결정·환급 승인처럼 표시하지 않는다.

## 후순위·보류 후보

- 수리 지연의 해결기준 판정: 의뢰일·인수일·보증 조건·부품 답변과 공식 기준 검수 후 확장. 기록 정리는 가능하되 특정 결과 계산은 보류.
- 예상 환급액: 공식 계산식·내용연수·기간·가산/예외 검수 전 보류. 2주 MVP의 필수 기능으로 추가하지 않기.
- 알림: 기록·동의·일정 입력 방식 검토 후 선택. 공식 예약 일정과 연결된 알림처럼 표현하지 않기.
- 모델 전체 자가진단 메뉴 자동 매핑: 전 모델 확보·검증을 전제하지 않기. 좁은 모델/문서 범위 또는 미확인 안내로 제한.
- 실제 접수·수리 일정 조회·부품 재고 조회·교환/환급 승인·고장 예측·자동 구매 데이터 연결: 이번 MVP 범위 밖.

## 성공을 어떻게 확인할 것인가

프로젝트 Agent가 준비되면 기존 서비스와 **같은 질문·같은 알려진 사실**로 비교한다. 새/동일 세션·실행일·전체 입력/응답·공식 출처를 기록한다. 실제 경험을 넣으면 개인정보를 가린다.

- 미확인 날짜·모델·진단을 만들어 채우지 않았는가?
- 사용자의 단계별 안내 요청을 따르고 결과를 기다렸는가?
- 리모컨·모델과 맞는 안전한 안내인가?
- 사건을 접수/점검/수리/재발로 구분했는가?
- 링크가 해당 주장과 제품을 뒷받침하는가?
- 상담 준비 요약에서 확인된 사실과 부족한 자료가 함께 보이는가?

향상률·상담시간 단축·고객 만족·예상 민원 감소 수치는 아직 없다. 구현 후 평가 결과로만 제시한다.

## 팀이 결정할 4가지

1. **핵심 대상:** ‘모델/증빙/이력이 일부 미확인인 LG TV 첫 이상·재발 사용자’를 타깃 제안으로 채택할지.
2. **우선 기능:** F01~F05를 좁은 범위의 핵심 흐름으로 채택하고 금액 계산·전체 모델 지원을 후순위로 둘지.
3. **공식 근거 검수 책임:** 규칙·LG 정책·자가 점검 안전 검수를 어떤 역할이 맡고 승인 기록을 어디에 남길지.
4. **데모/평가 범위:** 첫 이상·재발 2개를 필수, 지연은 검수 및 일정에 따라 선택할지.

현재 결정/담당자 지정/개발 기간 약속은 모두 미확정이다. 2주 프로젝트 계획이 있다고 해서 이 기능들의 2주 구현 가능성을 검증한 것은 아니다.
