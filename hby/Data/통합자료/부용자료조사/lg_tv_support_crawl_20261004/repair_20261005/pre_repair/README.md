- 지정 n8n 워크플로우에 수동 실행 → 로컬 수집 → 결과 검증 3단계를 구성하고 전체 실행 성공을 확인했다.
- 검증 실행: `runs/20261004T082735883553Z/`
- 선별 URL 13개 / 정상 본문 13개 / 원문 FAQ 쌍 18개 / 검토 필요 응답 0개. 원본 SHA-256 재계산 일치.
- 화면·소리 미출력, 소리만 출력, 음성 잡음·음량, 소리 울림, 전원 미작동, PC 연결 신호 없음 안내를 포함한다. 2차로 리모컨 미작동·매직 리모컨 연결/포인터·인터넷 연결/끊김·셋톱박스 오류 6개 자료를 보완했다.
- 1차 성공 실행의 7개·FAQ 12개에서 2차 성공 실행의 고유 13개·FAQ 18개로 확장했다. 실행별 수를 합산하지 않는다. 내용까지 동일한 Q/A 중복은 0행이었다. [증상별 공식 링크와 공백](runs/20261004T082735883553Z/coverage.md)을 먼저 보면 된다.
- **전체 TV FAQ 카탈로그를 수집한 것은 아니다.** 수집 대상은 lg_tv_crawler.py의 SEEDS에 명시되어 있다. FAQ는 각 스스로 해결 페이지에 실제 있는 질문·답변만 추출했다. 별도 FAQ 전체 목록 수집은 미수행.
- 시험 실행 2개는 6개 URL 중 정상 본문 5개·FAQ 10개였다. solutions-1777960은 제목 @@pageTitle의 비정상 응답이어서 정제에서 제외했다. 실패 응답도 원본·manifest에 보존했다. 검증 실행에는 대체 공식 자료를 추가했다. 실행별 자료를 합산해 고유 문서 수로 표현하지 않는다.

## 실행 방법

```powershell
& 'C:\Users\HanBuyong\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' 'D:\core-project\cx-agent-planning\부용자료조사\lg_tv_support_crawl_20261004\lg_tv_crawler.py' --output 'D:\core-project\cx-agent-planning\부용자료조사\lg_tv_support_crawl_20261004' --serve
```

도우미는 127.0.0.1:8766에만 바인딩한다. Docker n8n에서는 host.docker.internal:8766으로 접근하는 것을 실제 실행으로 확인했다. 외부 공개 포트·방화벽·Docker 마운트·보안 설정은 변경하지 않았다. 재부팅 후에는 도우미를 다시 시작해야 한다. 현재 작업에서 시작한 도우미 PID는 3652다. 예약 실행·자동 시작은 설정하지 않았다.

직접 일회 수집하려면 위 명령에서 --serve를 빼면 된다. URL 변경·재실행 시 robots 정책과 TV 관련성을 다시 확인한다. 모든 실행은 새 시각 폴더를 만들며 이전 원본을 덮어쓰지 않는다. 동시 실행은 도우미에서 거절한다.

## 정제·검증 방법

- 공식 검색으로 발견한 URL에서 추적 쿼리를 제거하고 문서 ID로 중복을 관리한다.
- 현재 robots.txt를 실행마다 보존하고 Python RobotFileParser로 수집 허용 여부를 검사한다. 로그인·내부 검색 API·차단 우회 없이 공개 상세 페이지만 2초 간격으로 조회한다.
- HTML의 view-content 영역만 파싱한다. 메뉴·스크립트는 본문에서 제외하고 dt/dd의 실제 Q/A만 선별한다. 생성형 모델로 FAQ나 고객 응답을 만들지 않는다.
- TV 제목·본문 길이·본문 선택자를 검사한다. 정상 본문이 아니면 원본만 보존하고 manifest에 검토 필요로 표시한다. n8n 검증 단계는 오류가 있으면 성공으로 처리하지 않는다.
- FAQ 수는 페이지 내부 Q/A 수이며 실제 문의 빈도·고객 사례 수가 아니다. 없는 FAQ는 빈 배열로 유지한다.
- 화면의 날짜는 후보로만 기록했다. 게시/수정일 의미의 수동 확인 전에는 확정 날짜로 쓰지 않는다. 수집 시각은 UTC다.
- 시험 4개 통과 및 실제 13개 HTML 원본 해시 재계산·동일 원본 재추출 일치 확인. 기능/내용 전체 전문가 검수나 모든 모델 적용 검증은 미완료다.

## Agent 활용과 주의

RAG의 증상별 점검 안내 **후보 자료**다. 일반 보상 규칙이나 Tool 판정 규칙으로 바꾸지 않는다. 모델별 메뉴, 안전 조건, 방문 점검 권고와 공용 콘텐츠 제한을 원문과 대조한 후 연결한다. FAQ 수를 서비스 비교 성능 지표나 수리 필요율로 사용하지 않는다.

공식 페이지에 미디어가 있으면 링크만 기록하고 이미지·동영상 파일은 다운로드하지 않는다. 기존 한국소비자원 사례와 기존 규칙 데이터는 수정하지 않았다. 새 자료 공개 재배포·GitHub 푸시는 별도 권리/개인정보 검토 후 진행한다. 이번 작업에는 커밋·푸시·PR가 포함되지 않았다.
