# 동일 시나리오 서비스 비교 실행지

최신 상태: 6개 시나리오 첫 응답 수집·1차 정리를 완료했다. [서비스비교_1차종합.md](서비스비교_1차종합.md) 참고. 아래는 재현·후속 비교를 위한 실행 절차와 빈 양식이며 ‘응답 없음’이라는 최신 상태 보고가 아니다.

## 실행 조건

processed/comparison_scenarios.json의 6개 질문은 가상 테스트 입력이다. 실제 소비자 데이터가 아니다. 실제 인터뷰 질문과 별개로 관리한다.

LG 자동 챗봇과 공식 문서에서 지원 범위를 확인한다. 프로젝트 Agent는 동일 범위 구현이 준비된 뒤 같은 입력으로 비교한다. 미구현 Agent의 예상 성능을 실제 결과와 비교하지 않는다.

로그인이나 개인정보가 필요하면 그 단계에서 중단하고 요구 항목만 기록한다. 사람 상담 연결·실제 예약·대금 결제는 이 테스트에 포함하지 않는다. 실제 서비스 시스템의 승인 결과를 만들어 기록하지 않는다.

## 테스트 입력 6개

- S01: 첫 증상, 소리만 나고 화면 없음
- S02: 신호 없음, 리모컨/셋톱박스 구분 미확인
- S03: 구입 11개월 추정·영수증 없음·무상 여부 문의
- S04: TV가 안 켜짐·본체 버튼과 리모컨 미확인
- S05: 두 번 수리 이후 재발·증빙 준비 문의
- S06: 재수리 의뢰 후 40일 지연·준비할 정보 문의

시나리오에 첫 고장이라고 쓴 것은 가상 입력 조건이지 첫 고장 사례를 확보했다는 뜻이 아니다.

## 공정하게 비교하는 방법

1. 같은 초기 질문을 입력한다.
2. 추가 질문을 받으면 시나리오에 적힌 사실만 제공한다. 적히지 않은 사실은 모른다고 답한다.
3. 안내 문서만 읽는 경로와 챗봇 대화 경로를 분리한다.
4. 응답·추가 질문·공식 출처·사용자에게 남은 행동을 원문 그대로 기록한다.
5. 확인된 조건과 미확인 조건을 구분했는지, 보상·고장 원인을 확정했는지 점검한다.
6. 모델·대화 시작일·새 세션 여부·로그인 여부·동일 입력을 기록한다. 이력이 섞이면 새 세션으로 구분한다.

시간을 측정하면 시작은 첫 질문 제출, 종료는 사전에 정한 목표에 필요한 안내를 확보한 때로 통일한다. 도구 대기·접속 실패와 실제 사용자 안내 시간을 분리한다. 시나리오가 실패하면 시간을 비워두고 실패/미완료 사유를 적는다.
