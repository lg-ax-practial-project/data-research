# 현재 조사 상태를 팀에 설명하기

## 말할 수 있는 것

“공식 표준답변과 피해구제 원본, LG 점검 가이드를 수집하고 TV 자료를 선별했습니다. 초기 고장에서도 교환·수리 선택과 보증·비용 문의가 존재하는 것은 질문 자료에서 확인했습니다. 다만 첫 고장 고객의 실제 행동·불편 빈도를 입증할 자료는 부족해서, 인터뷰와 동일 시나리오 서비스 비교를 준비했습니다.”

## 아직 말하면 안 되는 것

- 첫 고장 고객이 가장 어려워하는 단계나 어려움 비율을 확인했다.
- 기존 LG 챗봇은 상황에 맞는 추가 질문을 하지 않는다.
- 기존 서비스에 이력 관리나 상담 준비 기능이 없다.
- 우리가 상담 시간을 줄이거나 환급 가능성을 높인다는 효과가 입증됐다.

## 인터뷰 대상이 없을 때

팀원과 지인에게 최근 TV 이상 경험이 있는지 모집 문구로 물어본다. 실제 경험이 없는 팀원이 역할극을 하면 가상 사용성 테스트로만 기록한다. 역할극의 불편을 실제 첫 고장 고객의 불편으로 바꾸지 않는다.

모집이 되지 않으면 인터뷰 0명이라고 보고하고, 기능 설계는 공식 문서와 상담형 질문을 근거로 한 가설로 한정한다. 인터뷰 완료를 개발 진입의 절대 조건으로 새로 만들지는 않되, 실제 사용자 문제 검증이 남아 있음을 표시한다.

## 준비된 다음 작업

팀 결정에 사용할 [기능 선택안](../tv_mvp_review_20261002/MVP_기능선택안.md)과 [규칙·안전 검수 목록](../tv_mvp_review_20261002/규칙_안전_검수체크리스트.md)을 작성했다. 핵심 기능 5개·대표 데모 2개·검수 항목 10개를 제안했지만 팀 승인/개발 가능 일정/규칙 승인은 확정하지 않았다. 팀이 먼저 결정할 것은 대상, 핵심 기능, 검수 책임, 데모/평가 범위다.

최신 업데이트: 첫 응답 수집 6/6개·총 8턴을 보존하고 [서비스비교_1차종합.md](서비스비교_1차종합.md)에 통합했다. 4개 시나리오 입력 문장도 확보했다. 기존 점검·보증·증빙·서비스 연결 기능과 우리 기능 가설을 구분했다. 다음은 팀 검토·규칙/안전 검수·실제 고객 검증 공백 정리다. 가상 질문은 당장 더 늘리지 않는다. 아래 첫 응답 확보 기록은 이전 상태다.

자동 챗봇에 가상 시나리오를 실제 입력하고 응답을 기록하는 서비스 비교는 인터뷰 대상 없이도 가능하다. 조사 도구에서는 진입에 실패했으나 사용자는 본인 브라우저에서 상담창을 열고 첫 응답을 제공했다. S01 부분 실행으로 기록했고, 자가 점검 분기·전문 점검·증상 지속 여부 질문을 확인했다. 초기 입력과 전체 화면은 추가 확인이 필요하다. 후속 대화와 나머지 5개 시나리오를 이어서 검증한다. 사람 상담이나 실제 A/S 접수까지 수행하지 않는다.
