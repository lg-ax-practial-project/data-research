# 공기청정기 공식 근거 정제 초안

정제일: **2026-10-13**. 원문은 **2026-10-12 보존 수집본**이다. 정제일에 웹을 다시 확인한 자료가 아니다.

먼저 [근거 묶음 검토본](근거묶음_검토본.md)을 읽고, 기계가 읽을 데이터는 [근거 단위 JSONL](evidence_units.draft.jsonl)을 사용 검토한다. 공식 출처 12개에서 27개 근거 단위를 추렸다. 검색 색인과 임베딩은 아직 없다.

## 파일과 역할

| 파일 | 역할 |
| --- | --- |
| [근거 단위 JSONL](evidence_units.draft.jsonl) | 한 줄에 한 근거. 금액·날짜·예외·관련 근거를 함께 보존한 초안 |
| [복원한 표 2개](normalized_tables.json) | 케어 요금제 표의 열 정리, 이전설치 요금 XML 행 연결. 원본 수치는 수정하지 않음 |
| [근거 묶음 검토본](근거묶음_검토본.md) | 사람이 확인할 발췌와 해석. 문서 전체를 색인하지 않음 |
| [출처 분류](../../metadata/curation_source_registry_20261013.json) | 30개 출처의 용도·선정 여부 |
| [함께 검토할 근거](../../metadata/curation_review_groups_20261013.json) | 차이·적용 범위를 함께 봐야 할 9개 묶음과 제외 문구 2개 |
| [평가 질문 연결](../../metadata/evaluation_evidence_map_20261013.json) | 기존 20개 질문의 근거/처리 경로. 검색 색인에서 제외 |

## 필드 읽는 방법

- `evidence_id`: 이 조사 묶음 안의 근거 번호. 팀 공통 청크 ID로 확정한 값이 아니다.
- `segments`: 원문 발췌 또는 원표 구조를 정리한 표. 출처 파일·위치·해시를 포함한다. 수집 Markdown의 발췌는 웹 화면과 같은 형식이라는 뜻이 아니다.
- `official_sources`, `date_records`: 공식 URL·수집일·게시/시행/적용 관련 날짜. 미기재 값은 추정하지 않는다.
- `product_scope`, `contract_kind`: 제품과 계약 종류. 가전구독과 별도 케어십을 섞지 않는다.
- `curation_notes`: 조사자 해석, 함께 보존할 조건, 추가 확인할 계약 정보. 공식 인용문과 구분한다.
- `related_evidence_ids`, `review_groups`: 금액 충돌, 관리 주기 차이, 계약/고시 역할처럼 함께 검토해야 할 근거.
- `index_approved: false`: 아직 검색 색인용 최종 자료로 채택하지 않은 정제 초안이라는 상태값. 새로운 사용자 승인 절차나 팀 공통 API 필드가 아니다.
- `can_determine_customer_cost: false`: 이 자료만으로 고객의 확정 비용을 계산할 수 없다는 표시.

폴더 전체를 자동으로 읽어 넣으면 보고서·정답·충돌 문구가 함께 들어갈 수 있다. 향후 색인은 선정된 근거만 명시적으로 읽고 제품·계약·날짜·예외·연관 근거를 보존해야 한다. 원문 발췌와 조사자 해석을 하나의 공식 문장으로 합치지 않는다. 이 데이터 형식은 개인 정리용이며 검색 도구 명칭과 입출력은 팀 합의가 필요하다.

## 재현

[오프라인 정제 스크립트](../../scripts/curate_evidence_20261013.py)는 Python 표준 라이브러리만 사용한다. 네트워크·LLM·임베딩·비용 계산을 실행하지 않는다. `--source-root`에는 이 조사 묶음 경로, `--output-root`에는 **별도의 빈 결과 폴더**를 지정한다. 기존 결과와 원본을 덮어쓰지 않도록 출력 경로를 구분한다.

스크립트는 근거 묶음·출처 분류·검토 그룹·표·기본 검증을 재생성한다. README, 정제 결과 보고서, 평가 질문 연결, D 드라이브 반영 기록은 별도 작성 자료다.
