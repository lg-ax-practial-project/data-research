- LG/삼성에서 PDF 저장·출력·내보내기·상담 이력 통합·기간 밖 자료 재발급이 가능한지. 설명이 안 보인다고 ‘불가능’으로 판정하지 않는다.
- 여러 접수의 동일 기기 연결, 방문과 수리 구분, 고객의 재발 기록 추가가 기존 화면에서 되는지.
- 다른 채널의 상담사가 기존 이력과 고객 증빙을 실제로 이어받는지, 외부 정리물을 받아들이는지.

실제 접수정보·인증·고객 데이터가 없어 확인하지 않았다. 웹 페이지의 ‘내역’이라는 표현만으로 임상적인 수리 타임라인/동일 하자 증빙까지 확보됐다고 보지 않는다.

### 4.4 공개 자료로 다룰 수 있는 범위 / 현재 보류할 범위

- **검토 가능한 범위:** 공개 기준에서 상담 준비 필드를 만들고, 사용자가 직접 입력한 이벤트를 접수/방문/실제 수리/재발로 나누며 날짜·증빙의 확인/미확인을 표시하는 정리 흐름. 기관 기록의 대체본이 아니라 고객 준비용 초안으로 한정한다.
- **가상 시연 가능한 것:** 가상 수리 내역으로 타임라인·누락 필드·상담 요약의 출력 형식과 규칙을 확인할 수 있다. 그러나 실제 고객이 기록을 확보·정리·전달할 수 있는지, 부담이 줄어드는지는 검증되지 않는다.
- **현재 보류:** 인증 화면 자동 접근, 이력 대량 수집/동기화, 내부 접수번호 연동, 자동 외부 제출, 동일 하자/보증/환급의 확정 판정. 실제 고객 식별정보나 사업자 API·권한을 필요로 하는 범위다.
- **제안:** **범위 축소.** ‘이력이 없다’가 아니라 ‘이미 있는 고객 기록을 다음 상담에 쓸 수 있게 구분하는 부담’만 후보로 남긴다. 기존 이력 화면이 이를 충분히 제공한다면 별도 후보로서의 필요성은 더 줄어든다.

## 5. 후보 C — 구독 비용·계약 조건 이해

### 5.1 공식 자료에서 확인한 기존 기능

1. **이미 공개된 비용 설명:** LG 구독 서비스 안내에는 구독/구매 비교, 계약별 서비스·소유권 유의사항, 위약금·회수비/분실료·사은품·미납/연체·잔여 비용·제품 사용료·선납 반환금의 항목과 해지 진행 흐름이 있다. 공개 FAQ도 위약금의 기본요금 기준·경과기간별 비율과 추가 비용을 설명한다. **비용 항목을 알려주는 기능 자체가 새 공백은 아니다.** [S08·S09]
2. **계약 조건 우선과 개인 비용 확인:** S08은 실제 적용 내용이 계약서·상품설명서·약관에 따르며 정확한 해지 비용은 해지 시점 계약 상태에 따라 달라진다고 명시한다. 해지상담 신청→비용 안내·동의→회수·최종 정산의 경로가 공개돼 있다. 이는 공개 페이지에서 개인 금액을 즉시 조회했다는 뜻이 아니다. [S08]
3. **고객용 관리 경로:** S08에는 `마이페이지 > 구독관리 > 계약관리`의 해지상담 신청 경로가 표시된다. 과거 로컬 FAQ에는 계약기간을 계약서/계약관리에서 확인한다는 안내가 보존돼 있다. **이번에는 로그인 후 계약 상세 필드나 예상 해지금 표시·다운로드 기능을 확인하지 않았다.** [S08·L02]
4. **회수비 조건 재확인:** 이번 S09 본문에서 공기청정기/가습기/제습기 39,000원과 “26년 3월 24일 기준”, “계약서에 명기된 금액을 따름”을 확인했다. 과거 35,000원 가이드와의 전환 계약일은 이번 조사에서도 확인하지 않았다. 새로 본 공개 금액을 모든 과거 계약에 소급 적용하지 않는다. [S09·L02]

**해석:** ‘구독 비용 설명이 없다’나 ‘해지 방법이 없다’보다 **현재 자기 계약과 연결해 이해할 수 있는가**가 남은 문제다. 공식 문서만으로 고객의 혼동이나 비교 도구의 유용성을 확인한 것은 아니다.

## 6. 공개 문서 확인으로 바뀐 판단과 남은 확인

### 이번에 좁혀진 가정

- A: 점검 순서·버전 조건·진단·전문 지원 연결은 이미 있다. **맥락 반영이 기존 서비스에 전혀 없다는 주장도 철회해야 한다.** 공식 설명상 기능 존재와 실제 조건 반영 품질은 구분한다.
- B: 이력 조회 및 명세서 확인 경로가 있다. **‘자료 확보 수단 없음’ 대신 조건·보존기간·필드·내보내기·전달 범위를 미확인으로 남긴다.**
- C: 항목별 비용 안내·해지 절차가 이미 있다. 공백이 있다면 개인 계약에 대한 적용/이해인데, 이 부분이 바로 현재 공개 자료만으로 확인되지 않는 영역이다.
- 공통: **공개 API 존재 ≠ 고객 데이터의 익명 공개 ≠ 내부 진단/계약 API 접근권.** 공개 문서 부재 ≠ 기능/API 부재.

### 남은 확인 — 이번에는 수행하지 않음

| 후보 | 다음에 필요한 최소 확인 | 현재 중단 경계 |

| A | 허용된 실제 사용 비교로 이미 한 조치·모르는 조건·결과 입력에 대한 응답 확인. 모델별 안전 근거·공개 API의 실제 지원 필드 확인 | 앱/기기/인증이 필요하면 동의·권한 없이는 진행하지 않음. 위험 조작·부품 진단은 하지 않음 |

## 8. 짧은 작업 기록과 종료 상태

- 입력: 최신 지침, 2차 질문 문서의 후보/판단 기준, 기존 근거표 관련 항목.
- 수행: 공개 검색으로 경로 발견 → 공식 본문 대조 → 후보별 기능/자료 접근/미확인 영역 구분 → 본 결과 파일 새 작성.
- 안전: 이번 작업에서 비밀값·환경변수·인증정보 파일을 읽거나 출력하지 않았다. 로컬 비공개 내용의 웹 검색 전송, Notion·서브·사람 상담·로그인·인증·예약·신청·기기/API 실행 없음.
- 보존: 기존 파일·원본·설정 변경 없음. 전체 원문 복제나 부가 산출물 재생성 없이 본 문서에 출처·확인 위치·작업 기록을 함께 저장했다.
- 완료: A~C의 기존 공식 기능과 프로젝트 자료 확보 경계에 대한 **공개 문서 조사**. 실제 사용 비교·실제 고객 문제/효과·현재 로그인 후 화면·개인 계약 적용 검증은 미완료다.
- 주제·제품·기술 스택은 확정하지 않았다. 이 파일 작성 후 자동으로 인터뷰나 추가 실행을 이어가지 않는다.
