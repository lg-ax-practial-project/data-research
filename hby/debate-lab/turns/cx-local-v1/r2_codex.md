# Round 2 / Codex — 고객 과업·반복 노동·구현 제약 분석

- **발언 ID:** CX-R2-CODEX-000
- **Speaker:** Codex
- **역할:** 고객 과업 구조, 반복 노동, 구현 제약 분석
- **대상:** R1-CL, CX-R1-CODEX-001, AGY CLI Round 1 인계문
- **검토 범위:** 제공된 인계문과 로컬 자료 발췌 색인. 원본 전체와 외부 경쟁 서비스는 확인하지 않았다.
- **판단 상태:** 고객 수요·효과·차별화는 미검증 가설이다. 아래 경쟁 기능 중복은 조사할 가능성이며, 특정 서비스의 현재 기능을 확인했다는 뜻이 아니다.

Claude의 강점은 고객이 서비스를 찾을 **발생 시점**을 구체화한 점이다. AGY는 재촬영 이후 계산·일정·인계로 이어지는 **결과물**을 제시했다. Codex는 조건 변경과 작업 이력을 강조했다. 다만 세 참가자 모두 결과물을 생성하는 것과 고객의 일을 실제로 끝내는 것을 더 엄격하게 구분해야 한다.

### CX-R2-CODEX-007 — 가족별 식사 배정은 식품 인식보다 합의와 입력 유지가 어렵다

## 4. 이번 반론에서 얻은 구현·검증 기준

에이전트의 완료 범위를 다음처럼 나누어야 한다.

| 단계 | 완료의 의미 | 검증할 것 |
|---|---|---|
| 관찰 | 이미지에서 확인 가능한 항목을 추출 | 추출 오류, 누락, 근거 없는 추정 |
| 확인 | 필요한 사용자 응답·실측·추가 사진을 확보 | 불필요한 요청, 중요한 질문 누락 |
| 산출물 완성 | 조건을 반영한 자료·계획을 저장 | 규칙 위반, 수정 누락, 재현 가능성 |
| 고객 실행 | 고객 또는 담당자가 작업을 수행 | 미완료·재작업·되묻기, 총소요 시간 |
| 외부 처리 | 실제 접수·예약·기기 설정을 완료 | 연동 응답과 결과 확인 |

문서가 만들어졌다면 문서 완성이다. 실제 접수나 설정까지 완료했다고 표시하려면 그 결과를 확인해야 한다.

LangGraph는 확인 대기, 사용자 수정, 재촬영, 계획 갱신, 판단 보류와 종료 상태를 명시하는 데 사용할 수 있다. 다만 상태·이력 관리 자체는 세 후보군에 공통으로 필요한 구현이며 차별화의 증거가 아니다.

배포·검증 범위는 **공식 주제 하나, 고객 과업 하나, 지원 대상의 제한된 집합**으로 잡는 편이 검토 가능하다. 정답을 정의하기 어려운 설치 성공·식품 안전·절감 효과 대신, 우선 누락 정보 탐지·조건 준수·변경 반영을 검증할 수 있다. 이후 실제 고객 과업 수행으로 평가 범위를 넓혀야 한다.

비교 실험에서는 사진 촬영·재촬영·오류 수정·가족 확인까지 포함한 전체 부담을 측정해야 한다. 긴 안내문을 생성한 결과와 짧은 체크리스트를 비교해 에이전트가 더 낫다고 판단해서는 안 된다.

현재 조사 가치가 있는 구체적 과업은 **설치 상담 자료 완성(CX-C03), 예외 의류 분류(CX-C09), 식사 취소 후 변경 반영(CX-C07), 수리 상담 자료 완성(CX-C14)**이다. 이는 최종 선정이나 순위가 아니라, 고객 과업과 정답 범위를 비교적 구체적으로 정의할 수 있다는 잠정 판단이다.
