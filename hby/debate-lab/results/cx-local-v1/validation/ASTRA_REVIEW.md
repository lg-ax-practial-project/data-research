### 1. 전체 평가 요약

**최종 판단: 세 AI의 평가만으로 최종 후보를 채택할 근거는 부족하다. 다만 일부 후보는 범위를 축소하면 공식 과제에 맞는 MVP 조사 대상으로 남길 수 있다.**

이번 감사는 제공된 공식 안내, 기존 아이디어 색인, 세 AI의 최종 평가만 검토했다. 웹 검색, 파일 열람·수정, 서브 에이전트 사용 및 실제 실험은 수행하지 않았다. 다른 독립 검증자의 보고서는 참고하지 않았다.

이하 표기는 다음과 같다.

- **[확정 사실]** 제공 문서에서 직접 확인되는 내용. 외부 사실까지 검증했다는 뜻은 아니다.
- **[해석]** 문서 간 대조와 기술·기획 논리에 따른 판단.
- **[가설·미검증]** 사용자 조사, 데이터 확보, 구현 또는 실험이 필요한 주장.

**세 평가에 공통으로 남아 있는 논리적 약점**

| 약점 | 감사 판단 |
|---|---|
| 구체적인 상황 묘사를 고객 문제의 증거처럼 사용 | “건조 담당자가 옷을 망친다”, “변경 모델 때문에 전부 다시 확인한다”는 상황은 가능하지만 발생 빈도·손실·현재 해결 방식은 미검증이다. |
| 사진을 받는 과업과 사진이 필요한 과업을 혼동 | OCR 입력 편의, 시각적 상태 관찰, 개체 재식별은 서로 다른 가치다. 사진을 제거한 비교 실험이 필요하다. |
| 재촬영·보류를 신뢰성 확보 수단으로 과대평가 | 시스템이 **자신의 누락을 알아차리지 못하면** 재촬영 분기가 실행되지 않는다. 보류 기능의 존재만으로 안전성을 주장할 수 없다. |
| 사용자 확인을 오류 해결책으로 취급 | 사용자가 판단할 수 없는 문제여서 서비스를 찾았다면, 최종 확인을 요구하는 것은 원래 노동을 돌려주는 결과가 된다. |
| 카드·패킷·이력 생성을 Agent 가치로 평가 | 산출물이 실제 수신자에게 사용되는지, 다음 작업을 줄이는지가 확인되지 않았다. |
| 팀원 사진 확보와 평가 데이터 확보를 혼동 | 사진을 모으는 일과 설치 조건·의류 동일성·실패 원인의 정답을 만드는 일은 다르다. |
| 신규성과 기존 기능의 발전 정도를 혼합 | 대부분 기존 색인의 발전형이다. 개선된 상태 관리가 신규 서비스나 경쟁 우위의 증거는 아니다. |
| 구현 범위와 검증 범위의 불일치 | 여러 제품·규칙·단계를 제안하면서 OCR 정확도나 카드 생성 시간만 평가하는 경우가 있다. 핵심 약속을 시험하지 못한다. |

세 평가가 이러한 문제를 전혀 인식하지 못한 것은 아니다. 특히 Codex는 총부담과 완료 범위를 구분했다. **문제는 경고를 적어두고도 우선순위와 구현 가능성 평가에는 충분히 반영하지 않았다는 점이다.**

### 2. 공식 과제 적합성

**[확정 사실] 공식 안내에서 확인되는 기준**

- 8개 주제 중 **한 주제**를 선택하며 팀 간 중복 선택은 불가하다.
- 핵심·연계 기능 예시는 변경할 수 있다.
- Vision AI 이미지 인식과 재촬영 요청, LangGraph, 업로드·진행 상태·결과·이력, 클라우드 실행이 필수다.
- 멀티 에이전트·영상은 선택 사항이며 별도 가산점 항목이 아니다.
- LangGraph 비전 에이전트 설계와 서비스 검증·개선은 **각각 20점**이다.
- 프로젝트 시작은 11월 13일, 산출물 제출은 12월 14일이다. **제출까지의 구현·검증 기간은 약 4주 반**이다. 발표일까지 남은 기간을 최초 완성 기간으로 잡아서는 안 된다.

**추가 반론**

- 식기세척기라는 제품명만으로 공식 과제 밖이라고 단정하는 것도 과도하다. 판단 기준은 **선택한 주제의 고객 문제를 해결하는가**이다.
- 비LG 제품 입력의 금지 여부는 제공 안내에서 확인되지 않는다. 반대로 타사 제품의 문제를 LG 구매로 연결해야 한다는 요구도 없다.
- 다른 팀이 ②를 선호한다는 주장은 미검증이다. **세 AI의 선호는 다른 팀의 선택 확률을 뒷받침하지 않는다.**

### 3. 기술적 실현 가능성

#### Vision AI가 제공하는 가치부터 분리해야 한다

| 유형 | 관련 후보 | 기술적 판단 |
|---|---|---|
| 문서·라벨 입력 자동화 | `C02/E05`, `CAND-02`, `E06`, `CAND-09` | 수기 입력으로도 핵심 업무가 가능하다. OCR이 입력 시간을 얼마나 줄이는지 입증하면 유효한 Vision 역할이 된다. |
| 공간·상태 관찰 | `E01`, `C01`, `E03`, `E07` | 사진이 현장 맥락을 추가한다. 그러나 미관찰 영역·치수·원인·실제 색을 모두 확정하지는 못한다. |
| 동일 개체 연결 | `E02`, `E04`, `E06` | 의류·화분·용기를 지속적으로 연결하는 과업이다. 번호표를 사용하면 난도가 내려가지만 순수 Vision의 추가 가치도 다시 평가해야 한다. |
| 행동·성과 검증 | `CAND-04/06/08` | 사진으로 관찰 가능한 변경만 검증할 수 있다. 청소 품질, 적정 관수, 전력 절감을 완료 사진 하나로 증명할 수 없다. |

**[해석] 사진 없이도 구현 가능한 정도가 큰 후보**는 `E08/C09`, `CAND-10`의 일정 계산, `CAND-02`의 비용 비교, `E05`의 상담 요청 관리다. `E01`도 정형 치수와 제품 규격이 이미 제공되면 주요 계산은 사진 없이 가능하다.

이는 자동 탈락 사유는 아니다. 공식 과제는 모든 계산이 시각 모델이어야 한다고 요구하지 않는다. 다만 **사진이 없어도 동일한 고객 결과를 같은 부담으로 얻는다면 Vision 중심 서비스로서 설득력이 약하다.**

#### LangGraph가 실제로 할 일이 있는가

**[해석] 다음처럼 상태와 의존성을 관리한다면 의미가 있다. 구현 여부는 모두 미검증이다.**

| 후보 | 의미 있는 LangGraph 작업 | 단순 챗봇에 머무는 경우 |
|---|---|---|
| `E01` | 제품·장소 변경 시 영향받는 조건만 무효화하고, 필요한 증거를 다시 요청한 뒤 비교표 갱신 | 매번 사진과 모델명을 넣고 설치 조언을 다시 생성 |
| `E02` | 라벨–의류 연결 상태, 미확인 의류, 인계자·인수자 확인 상태를 유지하고 모호한 연결을 차단 | 라벨 설명과 건조 제외 목록을 한 번 출력 |
| `E03` | 실패 사례–수정 행동–주행 결과를 연결하고 다음 확인 작업 결정 | 장애물 사진에 정리 팁 제공 |
| `E04` | 기존 지시·신규 질문·상충 답변·미완료 작업을 연결하고 답변 대기 후 재개 | 화분 사진에 관리법 답변 |
| `E05/CAND-02` | 상담 후속 요청에 필요한 자료 선별, 견적 누락 확인, 계산 입력 변경에 따른 재계산 | 명판 요약 후 일반적인 수리·교체 조언 |
| `E07` | 가족 선호의 충돌·필수 조건·후보 탈락 사유를 보존하고 구성안 갱신 | 사진을 보고 색상 추천 |
| `E08` | 조치·불편·유지·원복 상태를 기록 | 절약 팁과 알림 제공. 이 수준에서는 일반 업무 앱과 차이가 작음 |

재촬영은 무조건 반복하는 단계가 아니다. **흐림, 대상 누락, 조건 불일치, 추가 관찰로 해소할 수 없는 불확실성**을 구분해야 한다. 마지막 경우에는 수기 입력·외부 확인·보류로 끝나야 한다.

또한 다음은 공통 구현 부담이다.

- 새 사진이 이전 사실을 덮어쓸 때 근거와 버전 보존.
- 사용자 수정 후 하위 결과 재계산.
- 대기·재개, 중복 요청, 실패한 작업 재시도 처리.
- 공유 링크의 접근 범위와 이력 분리.
- 진행 상태와 실제 서버 작업 상태의 일치.

**LangGraph 노드를 여러 개 만든 것만으로 이 문제가 해결되지는 않는다.**

#### 일정 내 MVP

**[해석] 한 제품군·한 고객 사건·한 핵심 루프라면 조건부로 가능하다. 팀 역량과 가용 시간은 미검증이다.**

- **상대적으로 범위 통제가 쉬움:** `E07` 제한된 제품·샘플 비교, `E06` 확인된 원포장–번호 용기 연결, `C02/E05` 제한된 상담 자료 생성.
- **핵심 기술 시험을 먼저 통과해야 함:** `E01` 변경 영향 관리, `E02` 의류 연결, `E04` 화분 인계.
- **실물 자원 확보가 선행되어야 함:** `E03` 실제 로봇 주행.
- **현 범위로는 과대:** `CAND-01` 복수 공간·반입·설치 순서, `CAND-02` 3개 품목·자가점검·구독 포함 비용 비교, `CAND-03` 위험 선별·세탁/건조/스타일러 배정, `CAND-10` 다중 가사 일정.

11월 23일 기획 발표 전에는 핵심 위험 가설을 시험하고, 11월 30일 전후에는 배포된 전체 흐름을 확보해야 이후 검증·개선 시간을 남길 수 있다. 이는 **권고 일정이며 현재 진행 상태가 아니다.**

### 4. 후보별 치명적인 약점과 개선안

아래의 “치명적”은 **해결하지 않으면 해당 후보의 핵심 가치 주장을 유지하기 어려운 문제**를 뜻한다.

| 후보 ID | 치명적인 약점·반대 근거 | 개선안 |

### 6. 과대평가 / 과소평가 가능성

#### 과대평가

- **`CAND-01`의 38/40:** 고객 수요, 공식 규격 확보, 공간 정답 구축이 미검증인데 거의 만점이다. 입력 누락 탐지와 실제 설치 실패 예방도 구분되지 않았다.
- **`CAND-03`의 구현성 5점:** 라벨 판독, 외형 기반 선별, 실물 연결, 기기 코스 매핑, 인계 검증을 동시에 요구한다. 특히 선별 단계의 누락이 후속 보류로 복구되지 않는다.
- **`CAND-04`의 차별성 5점:** 기존 `R-01~04`와 강하게 겹치며 외부 서비스 비교도 없다.
- **`CAND-09`의 구현성 5점:** 번역 결과 출력은 쉬워도 모델별 조작 상태와 정확한 버튼 위치·순서를 연결하는 것은 별도 문제다.
- **Claude의 `C03` 구현성 4점:** 등록된 옷이 존재한다는 정답은 명확해도, 사진에서 식별 가능한 증거가 충분한지는 별개의 문제다.
- **공통 아키텍처 재사용에 따른 즉시 후보 전환:** 업로드·이력 기능은 재사용할 수 있지만 도메인 규칙·정답 데이터·참여자는 다시 확보해야 한다.

AGY의 합계는 동일 가중치의 주관 점수이며 공식 100점 평가와 대응하지 않는다. “가설”이라고 표시해도 높은 정밀도의 순위 근거가 생기지는 않는다.

#### 과소평가

- **`E07/C10` 인테리어 비교:** 취향에 단일 정답이 없다고 검증이 불가능한 것은 아니다. 필수 조건 누락, 비교 시간, 가족 간 미해결 쟁점, 실제 선택 후 평가로 시험할 수 있다.
- **`E04/C05` 일반 화분 인계:** 틔운을 직접 사용하지 않는다는 이유만으로 공식 적합성을 낮추는 것은 안내보다 좁은 해석이다.
- **`E06` 소분 표시:** 신규성은 낮지만 과업 범위를 통제하기 쉽다. 최첨단 재식별보다 완성도·개선 증거를 확보하기 유리할 가능성이 있다.
- **OCR 중심 후보:** 사진이 대체 불가능해야만 유효한 것은 아니다. 실제 입력 부담을 크게 줄인다면 공식 Vision 요구와 고객 가치에 기여할 수 있다.

**[해석] 참신함보다 완성도와 검증을 중시하는 공식 평가를 고려하면, 기술적으로 어려운 후보가 자동으로 유리하지 않다.**

### 8. 후보별 최소 검증 실험

**아래는 제안이며 실행 결과가 아니다.** 특정 사진 수를 확보했다고 충분한 검증이 되는 것도 아니다.

공통적으로 세 가지를 분리해서 비교한다.

1. **현재의 단순한 방법:** 체크리스트, 사진 카드, 번호표, 메신저, 수기 라벨.
2. **같은 자료·도구를 제공한 범용 멀티모달 대화.**
3. **제안한 상태 관리형 서비스.**

총부담은 등록·촬영·재촬영·입력·수정·확인·상대방 참여를 포함한다. 사진을 제외한 버전도 비교하여 Vision의 추가 기여를 확인한다.

| 후보 | 최소 실험 | 핵심 측정·중단 근거 |
|---|---|---|
| `E01/CAND-01` | 공식 조건이 있는 모델 쌍과 실제 측정 공간으로 변경 전후 확인 항목 작성 | 필수 항목 누락, 잘못된 증거 재사용, 불필요한 재확인, 총시간. 문항 감소와 누락 증가가 동반되면 실패 |
| `C01` | 변화 없는 재촬영, 확인 가능한 변화, 기준 사진에 없는 영역을 구분해 비교 | 조명·각도에 의한 오탐, 변화 누락, 발생 시점의 과잉 추론 |
| `C03/E02/CAND-03` | 유사 옷·뒤집힘·가림·미등록 옷이 포함된 인계 시험. 선별 기능을 시험할 때는 전체 라벨을 별도로 확인 | 잘못된 연결, 놓친 건조 금지 의류, 보류 후 해결률, 두 사람의 총시간 |
| `C04/E03/CAND-04` | 같은 구역에서 기준 주행과 수정 주행 반복. 앱 기록과 실제 도달을 함께 확인 | 주행 결과, 준비 노동, 실패 재발. 금지구역을 늘려 중단만 줄인 결과를 청소 개선으로 계산하지 않음 |
| `C05/E04/CAND-06` | 인계자·인수자 쌍으로 번호표+메신저와 비교. 누락·상충 지시 포함 | 화분 오연결, 질문하지 않은 누락, 지시 검색 시간, 인계자 준비 노동 |
| `C06/E06/CAND-05` | 원포장–번호 용기 연결 후 용기 이동·일부 사용·라벨 손상 상황 시험 | 잘못된 정보 연결, 수정 노동, 수기 라벨 대비 시간. 보관 안전성은 이 실험으로 입증하지 않음 |
| `C02/E05` | 실제 요구 항목 또는 명시적으로 모의인 요청을 이용해 수신자 관점의 자료 검토 | 추가 질문 수, 필수 누락, 재작성 시간. 모의 요청 결과는 실제 상담 효과로 일반화 금지 |
| `CAND-02` | 견적과 계약 조건이 확인된 사례에서 비용 계산·조건 변경 시험 | 누락 비용, 단위·기간 오류, 가정 변화에 따른 결론 변화. 계산 정확성과 추천 신뢰를 별도 측정 |
| `C07` | 작업별 공식 방문 안내와 실제 공간을 대조 | 필수 준비 항목 누락, 잘못된 준비 완료 판정 |
| `C10/E07/CAND-07` | 실제 샘플·공간에서 사진 앨범/비교표와 후보 갱신 서비스를 비교 | 필수 조건 준수, 비교 시간, 의견 충돌 처리, 선택 후 사용자 평가 |
| `C09/E08/CAND-08` | 텍스트 행동 기록과 사진 확인 기록 비교 | 사진이 추가로 발견한 유효 정보, 촬영 부담, 유지 여부. 에너지 절감량은 별도 계측 없이 주장하지 않음 |
| `C08/CAND-09` | 한 모델·한 작업을 목표 사용자에게 수행하게 함 | 잘못 누른 버튼, 도움 요청, 과업 성공, 이해도. 번역 문장 정확도만으로 통과시키지 않음 |
| `CAND-10` | 한 세탁 마감 과업의 기기·코스·의류 제약을 명시하고 일정 계산 | 제약 위반, 실행 불가능 일정, 수동 일정 대비 부담. 사진이 일정에 더한 정보를 별도 기록 |

**평가 설계에서 반드시 고칠 점**

- 같은 옷·집·화분의 유사 사진을 무작위로 나누면 일반화 성능이 부풀려질 수 있다. **새 개체 적응**과 **등록 개체의 다른 시점 재식별**을 별도로 평가해야 한다.
- 설치 가능성·고장 원인 등의 정답을 모델 응답으로 만들면 안 된다. 확보한 문서·측정·적격 검토의 범위를 밝혀야 한다.
- “틀린 확신보다 보류가 많은가”는 충분한 판정 기준이 아니다. 전부 보류해도 통과할 수 있다. **자동 처리한 결과의 오류율과 실제 완료 가능한 비율**을 함께 본다.
- 모의 시간 이동은 시연 방법이다. 실제 사용 결과나 장기 효과의 검증을 대체하지 않는다.
- 개선 전후 비교는 미리 정한 별도 사례에서 수행하고, 단순 대안에도 같은 학습 기회를 제공해야 한다.

### 9. 검증 불가능한 주장 목록

다음은 **이번 제공 자료만으로 검증할 수 없는 주장**이다.

| 주장 | 필요한 추가 증거 |
|---|---|
| 고객이 반복적으로 큰 불편을 겪고 비용을 지불하거나 앱을 사용할 의향이 있다 | 대상 고객의 실제 사건·현재 해결 방법·사용 행동 |
| 촬영·재촬영을 포함해 고객 노동이 감소한다 | 단순 대안 대비 전체 과업 비교 |
| 재촬영 최대 1~2회가 적절하다 | 과업별 완료·이탈·추가 정보 획득 자료 |
| 바구니 의류 재식별이 실용 수준이다 | 가림·유사 의류·미등록 의류를 포함한 평가 |
| 역지목으로 전체 라벨 확인을 안전하게 줄일 수 있다 | 선택되지 않은 의류까지 포함한 누락 평가 |
| 지도와 현장 사진으로 청소 실패 원인을 구분할 수 있다 | 실제 주행과 원인 확인 자료 |
| 물주기 사진으로 적정 관리 완료를 검증할 수 있다 | 작업별 관찰 가능성 및 독립 확인 자료 |
| 환경 사진으로 전력 누수·요금 급증 원인을 설명할 수 있다 | 계측·사용 시간·요금 조건·환경 자료 |
| 패킷이 실제 LG 상담·설치 과정에서 사용된다 | 수신 채널의 요구 형식과 실제 활용 확인 |
| 수리·구매·구독 비용 비교가 충분하고 중립적이다 | 실제 계약 조건, 누락 비용, 가정 민감도 |
| 기존 ThinQ·AI DD·고객지원과 중복되지 않는다 | 현재 공식 기능과 사용 흐름 비교 |

| 제시한 데이터 수를 기간 내 수집할 수 있다 | 장비·참여자·자료 이용 조건·정답 작성 담당 확보 |
| 한 후보에서 다른 후보로 즉시 전환할 수 있다 | 재사용 가능한 구현 범위와 새 도메인 데이터 준비 수준 |
| 공식 링크가 각 서술을 현재 그대로 뒷받침한다 | 링크 원문 확인. 이번 감사에서는 열람하지 않음 |

주거 사진·지도·고지서·견적·제조번호·공유 링크의 데이터 처리도 설계가 없다. 특히 **동의받은 사진 확보, 필요한 부분만 수집, 제3자 노출 제거, 접근 범위·삭제 정책**은 클라우드 MVP에서 실제 구현해야 할 항목이다.

### 10. 최종 판정과 미해결 질문

**최종 판정: “조건부 조사 진행, 최종 채택 근거는 부족”이다.**

세 AI 평가에서 유효한 부분은 고객 과업을 자료 준비·조건 갱신·인계·재시험으로 구체화한 점이다. 그러나 그 구체성이 수요, Vision의 추가 가치, 데이터 확보, 기간 내 성능을 증명하지는 않는다.

**검증 완료 — 문서 대조 수준**

- 공식 필수 기능·평가 배점·제출 일정 확인.
- 주요 후보와 공식 주제의 연결 및 경계 검토.
- 기존 색인과의 강한 중복 관계 확인.
- 이름이 비슷하지만 다른 과업을 하나로 묶은 문제 식별.
- 제안한 실험이 핵심 가치 주장을 검증하지 못하는 부분 식별.
- 사진 관찰, 사용자 보고, 실제 생활 성과가 혼합된 주장 구분.

**검증 필요 — 아직 완료되지 않음**

- 실제 고객의 문제 빈도·현재 대안·서비스 참여 의향.
- 사진이 추가하는 정보와 전체 노동 감소.
- 후보별 핵심 인식 오류와 보류 정책의 효과.
- 공식 제품 자료·샘플·상담 사례·실물 장비 확보.
- LangGraph 상태 관리와 배포 서비스의 실제 동작.
- 생활 결과와 기존 서비스 대비 차별성.

최종 선정 전에 해결해야 할 질문은 다음 다섯 가지다.

1. **고객이 맡기려는 끝점은 무엇인가?** 자료 완성, 인수 확인, 실제 문제 해결 중 하나를 명확히 정했는가?
2. **사진을 제거하면 무엇이 실제로 나빠지는가?** 입력 시간인지, 누락인지, 실물 연결인지 측정할 수 있는가?
3. **시스템이 모른다는 사실조차 모르는 경우를 어떻게 발견하는가?** 가려진 옷·설치 조건·누락 지시를 포함하는가?
4. **12월 14일까지 확보 가능한 정답과 참여자는 누구인가?** 사진 수보다 이를 먼저 확정해야 한다.
5. **단순한 대안보다 낫지 않으면 범위를 축소하거나 후보를 바꿀 것인가?**

현재 자료에서 가장 필요한 다음 증거는 추가적인 AI 합의나 점수표가 아니라, **제한된 실제 과업에서 단순 대안보다 오류 또는 총부담을 줄였다는 비교 결과**다.
